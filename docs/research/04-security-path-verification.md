## Pundit / CanCanCan facts used by the review (from their docs)

- Pundit: `Pundit.policy_scope!(user, scope)` raises `Pundit::NotDefinedError` if no scope class exists; messages `"unable to find scope \`#{find(object)}::Scope\` for \`#{object.inspect}\`"` / `"unable to find policy \`#{find(object)}\` for \`#{object.inspect}\`"` (`lib/pundit/policy_finder.rb:64, 72`, `lib/pundit/error.rb:70`). `Pundit::PolicyFinder.new(obj).policy` / `.scope` return nil when missing.
- CanCanCan: rules defined **only with a block** make `accessible_by` **raise**; an SQL string or scope must accompany the block (docs "Define abilities with blocks → Fetching Records"). A scope + block cannot be combined with multiple `can` for the same action/model.
- CanCanCan: `can :read, User, [:username]` makes `can? :read, @user` **true** and `accessible_by` return all users (docs "Accessible attributes"). `ability.permissions` returns `{can:, cannot:}` but needs a concrete user's ability. `accessible_by(ability, :update)` takes the action as 2nd argument; default action `:index` (aliased by `:read`).

## Key learnings

1. Execution::Next skips type `authorized?` for any scoped list/connection item whose concrete type has `reauthorize_scoped_objects(false)`, even when `scope_items` returned the same object.
2. Because of (1), in Next `nodes(ids:)` returns such objects without `authorized?`, since `Node.scope_items` is a no-op.
3. By default a failed type `authorized?` produces a silent `null` with no `errors` entry in both runtimes, while a `loads:` miss produces a visible ExecutionError — an existence oracle.
4. In Next, without extra `lazy_resolve` registrations, a lazy returned from `authorized?` is never synced and counts as authorized. Use `.load`.
5. With no `use` call the schema uses `Schema::Warden`, which calls `visible?` per query.
